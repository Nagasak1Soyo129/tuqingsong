# 图轻松

**在线图片与 PDF 工具箱 —— 全部在浏览器里完成,文件不上传服务器。**

🔗 **在线使用:<https://tuqingsong.pages.dev>**

不用注册、不用安装、没有广告。

## 为什么做这个

你在百度搜「在线图片压缩」,前几名**全部**是把你的图片上传到他们服务器的。

证件照、身份证、合同、病历、简历 —— 这些图你真的愿意传到陌生人的服务器上吗?

图轻松的做法完全不同:**所有处理都在你自己的浏览器里完成**,图片一个字节都不会离开你的设备。
你甚至可以在断网状态下使用它。

这是纯前端架构带来的能力,不是营销话术。打开浏览器开发者工具的 Network 面板,
随便处理几张图,你会看到除了网页本身,没有任何上传请求。

## 账号与支持系统

- 注册:用户名 + 邮箱 + 密码(邮箱唯一);登录支持用户名或邮箱
- 密码加盐哈希(PBKDF2)存 Cloudflare KV,不存明文
- 感谢码激活后绑定账号,支持权益跨设备生效
- 感谢码在后端校验(Cloudflare Pages Functions),不在前端暴露

## 技术栈 / 部署

- 静态站点:`index.html` + `style.css` + `app.js`
- 后端:Cloudflare Pages Functions(`functions/api/*`),账号数据存 Cloudflare KV(绑定名 `USERS`)
- 环境变量:`MASTER_CODE`(主控码)、`VALID_CODES`(有效激活码列表)、`XH_APPID`/`XH_SECRET`(虎皮椒支付)
- 部署:GitHub 仓库 → Cloudflare Pages(Git 集成自动部署)
- PDF 处理:引入 [pdf-lib](https://github.com/Hopding/pdf-lib)(MIT)做合并/拆分/页面管理/叠加内容,**自托管在 `vendor/`**(不走 CDN,避免国内 CDN 被墙导致功能失效),只在用到 PDF 工具时懒加载,不影响首屏速度
- **中文水印/页码的实现**:pdf-lib 内置字体不支持中文,嵌入 CJK 字体又要 5~15MB。改用 **canvas 把文字渲染成 PNG(3 倍超采样)再贴进 PDF**,天然支持中文与任意字体,零字体文件开销。代价是水印文字不可选中/搜索(对水印和页码无影响)

## 实现上有意思的几点

全程没引入打包器、没上框架,几个地方是自己写轮子解决的:

- **ZIP 打包** —— 手写 CRC-32 表 + ZIP 的局部文件头 / 中央目录 / EOCD 结构,
  store 模式(不压缩)。为了不引 100KB 的 JSZip,自己写了约 80 行。
- **PDF 生成** —— 同样手写 PDF 的 xref 表与对象结构,把 JPEG 以 `DCTDecode`
  直接塞进 PDF(不重新编码,所以转出来的 PDF 不损画质)。
- **中文水印 / 页码** —— 这处最绕。pdf-lib 的内置字体**不支持中文**,
  要嵌 CJK 字体得背 5~15MB 的字体文件。解法是**用 canvas 把文字渲染成
  PNG(3 倍超采样防模糊)再 `embedPng` 进 PDF** —— 浏览器天生有中文字体,
  零字体开销。代价是水印文字不可选中(对水印来说无所谓)。
- **平铺水印** —— 铺满整页且溢出对称,否则页边会留下没水印的空白。
  列数得用 `ceil((页宽 - 水印宽) / 步长) + 1`,少算自己那一格就会出现露白。
- **纯 JS 的 MD5** —— Web Crypto 不提供 MD5,而虎皮椒支付签名要求 MD5,只能自己实现。
- **图片压到指定大小** —— 对质量参数做二分搜索,8 次迭代逼近目标体积。

## 推送代码(注意代理)

GitHub 在国内**时通时不通**。仓库级代理配置已移除,因为代理没开时它会**直接导致推送失败**
(`Failed to connect to github.com:443 over proxy 127.0.0.1`)。

- 默认直接推:`git push origin main`(实测通常可用,只是偶尔慢)
- 若直连超时,先开 v2rayN,再临时指定代理:
  `git -c http.proxy=http://127.0.0.1:10808 -c https.proxy=http://127.0.0.1:10808 push origin main`
